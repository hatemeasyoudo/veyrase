# Обновление 24.11.2026

База изменений: hatemeasyoudo/veyrase, commit 0e99e4f.

1. В Supabase SQL Editor выполнить `supabase/analytics.sql` **до публикации кода**. Миграция добавляет только nullable country; её можно повторять. Не запускать сброс базы.
2. Опубликовать изменения в GitHub; связанный проект Vercel должен развернуть новую версию. Доступ к этому проекту и автоматическая публикация в этой сессии не проверены.
3. Проверить заголовок вкладки, отсутствие temporary mark, /admin → Статистика → 7/30/90 дней.
4. Посетить магазин с включённой аналитикой; страна появится после первого записанного посещения на Vercel. Локально GEO остаётся неопределённым.

Дни считаются по UTC (сохранена существующая модель). Посетители уникальны по browser cookie в пределах дня/периода, а не по человеку. Старые данные по дням доступны; история GEO не восстанавливается. Страна — первая определённая для браузера, IP не сохраняется. VPN влияет на результат. GPC и DNT продолжают отключать сбор. Данные не являются точным подсчётом людей.

Заказы по дням относятся к дате создания; оплаты — к дате подтверждения. Верхняя существующая метрика оплаченных заказов относится к заказам, созданным за период: она может отличаться от суммы оплат по дням.

Без миграции запросы, записывающие посещения, завершатся ошибкой: сначала SQL, затем код. Для отката вернуть предыдущий код; колонку country можно оставить.

Проверка: Node syntax, git diff --check, интеграционный тест с PostgreSQL-совместимым PGlite. Тест не подключается к рабочей базе. Запуск: `npm install --no-save @electric-sql/pglite`, затем `node --test tests/analytics.test.mjs`.
